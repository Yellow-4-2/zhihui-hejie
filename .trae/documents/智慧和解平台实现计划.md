# 智慧和解平台 — 实现计划

## Context（背景）
依据《"智慧和解"平台操作手册》（已从 docx 提取至 `_temp_docx/extracted.txt`）构建一个消费纠纷"智慧和解"平台。手册定义了 4 个角色端、8 个和解状态及完整流转。目标：Vue3+TS、Vant 4、移动优先且自适应桌面、Pinia+Mock 数据（无后端）。项目目录当前为空（仅含临时提取的手册文件）。

## 技术栈与关键决策
- **脚手架**：Vite + Vue3 + TypeScript（用 `npm create vite` 生成正确版本，再装依赖）。
- **UI 库**：Vant 4（`unplugin-vue-components` + `@vant/auto-import-resolver` 自动按需引入）。
- **状态**：Pinia + `pinia-plugin-persistedstate`（localStorage 持久化，刷新不丢数据）。
- **路由**：Vue Router 4。
- **移动适配**：`postcss-px-to-viewport-8-plugin`，设计宽 375，**排除** `src/views/pc/**`（PC 端用原始 px 宽表格）。
- **响应式策略**：按路由前缀切分布局，**不做设备嗅探**：
  - `/m/:role/*` → `MobileLayout`（底部 tabbar + `.mobile-shell` 桌面端居中手机列）
  - `/pc/*` → `PcLayout`（侧边栏+顶栏，宽表格）
  - `/` → 角色选择器（演示入口，可在 4 个端之间切换）

## 角色与状态流转
状态枚举：`PENDING 待受理 / ACCEPTED 已受理 / REJECTED 不受理 / IN_PROGRESS 和解中 / COMPLETED 和解完成 / FAILED 和解失败 / FINISHED 已完结 / EVALUATED 已评价`

流转：发起→待受理→(消保委核实)→不受理|已受理(分配企业)→(消保委提建议)→和解中→(消费者确认/企业完成和解)→和解完成|和解失败→(消保委回访)→已完结→(消费者评价)→已评价

## 核心设计

### 1. 状态-动作矩阵（单一数据源，驱动所有按钮）
`src/config/statusActionMatrix.ts` 定义 `Record<CaseStatus, ActionDef[]>`，每个 `ActionDef` 含 `type/label/variant/roles`。`useCaseActions(case, role)` 过滤出当前角色可用动作，`ActionSheet.vue` 据此渲染按钮并分发到 store。
- 待受理：消保委 `核实受理/不受理`；消费者/企业 `查看`
- 已受理：消保委 `发起和解建议`；其余 `查看`
- 和解中：消保委 `和解确认`；消费者 `同意/不同意`；企业 `完成和解`
- 和解完成：消保委 `回访确认`；其余 `查看`
- 已完结：消费者 `评价`；其余 `查看详情`
- 失败/不受理/已评价：全员 `查看详情`

### 2. ReconciliationCase 数据模型（types/index.ts）
`id/caseNo/status/consumerName/consumerPhone/enterpriseId/enterpriseName/commodity/amount/description/initiator/timeline[]/suggestion?/completionVoucherImages?/rejectRemark?/returnVisitRemark?/evaluation?`。`timeline` 记录每次状态变更。

### 3. Store
- `useReconciliationStore`：cases 数组（首次从 mock 种子）；getters `getById/countsFor(role)/casesForRole(role)/byStatus(status,role)`；actions `initiateCase/acceptCase/rejectCase/proposeSuggestion/consumerConfirm/committeeConfirm/completeReconcile/returnVisit/evaluate/resetMock`，每个 action 追加 timeline 并更新 updatedAt。
- `useUserStore`：currentUser + 角色判断 + loginPc/loginMobile/logout。
- `useCaseLibraryStore` / `useEnterpriseStore`：静态 mock 查询。

### 4. Mock 数据
- users：admin/123456（消保委PC）、cmobile/123456（消保委移动）、13800000001/123456（消费者张三）、13900000001（企业海尔客服）等。
- enterprises：海尔/美的/苏宁/格力。
- caseLibrary：6 条各品类案例含建议文本。
- cases：8 条覆盖全部状态（CASE-2022-0001~0008），含完整 timeline。

### 5. 路由
- 公开：`/`（角色选择）、`/login/pc`、`/login/m/committee|consumer|enterprise`
- PC：`/pc/*` 13 个页面（PcLayout）
- 移动：`/m/:role`(首页)、`/m/:role/initiate`、`/m/:role/list/:status`、`/m/:role/case/:id`、`/m/consumer/evaluate/:id`（MobileLayout）
- guards：`/pc/*` 需 COMMITTEE_PC 登录；`/m/:role/*` 需匹配角色登录；`:role` 不匹配则跳对应登录页。

## 实现步骤（顺序）
1. 用 `npm create vite@latest . -- --template vue-ts` 脚手架，装依赖（vue-router/pinia/pinia-plugin-persistedstate/vant/@vant/use/@vant/auto-import-resolver/unplugin-vue-components/postcss-px-to-viewport-8-plugin/sass）。
2. 配置 `vite.config.ts`（Vant 自动引入 + `@` 别名）、`postcss.config.js`、`tsconfig.json`、`index.html`、`main.ts`、`styles/*`。
3. 写 `types/index.ts`、`config/*`（statusMeta + statusActionMatrix + constants）。
4. 写 `mock/*`、`utils/*`、`stores/*`。
5. 写 `layouts/*`、`composables/*`、`components/*`。
6. 写 `router/*`（含 guards）。
7. 写 `views/portal/*`（角色选择 + 登录）。
8. 写 `views/pc/*`（13 个 PC 页面 + 抽屉详情）。
9. 写 `views/mobile/*`（首页/列表/详情/发起/评价）。
10. 清理 `_temp_docx` 临时目录，运行 `npm run dev` 自测全流程，`npm run build` 类型检查。
